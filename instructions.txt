0. WHAT WAS WRONG, AND WHAT IS NOW TRUE
---------------------------------------
The first preview connected “london_rails” / “lane_uk_shop” and imported a
hard-coded wardrobe. That was a code defect, not a user error. Those
placeholder accounts are purged on the next signed-in load.

Now:

  • Connect Vinted creates an extension-mode account in status
    extension_offline until Lane Bridge heartbeats OR a session token
    is captured (phone QR / cookies API).
  • Connect eBay 302s to official eBay OAuth. No shop is inserted until
    the callback stores real tokens (AES-256-GCM sealed with
    BETTER_AUTH_SECRET).
  • Vinted jobs sit in waiting_for_browser unless a sealed refresh
    token is on the account — then the worker runs them like eBay.
  • eBay jobs run on the server via Inventory API.
  • Inventory is 10-per-page with Select page / Select all / Delete.
  • Billing Checkout hits Stripe when keys exist; otherwise the
    switcher only changes caps (preview).

If something “isn’t working” in the Grok live preview, that is expected:
the preview cannot run a real Chrome extension or complete eBay OAuth
without the owner’s developer keys. Failures must stay honest.

6. VINTED / LANE BRIDGE
-----------------------
There is no official Vinted public write API. Lane uses the seller’s
browser session, the same class of tool as Vindy:

  extension/manifest.json     MV3, host_permissions for vinted.co.uk
  extension/background.js     pairing token, /api/bridge calls
  extension/content-vinted.js isolated world, 4s poll, job relay
  extension/injected.js       MAIN world fetch() to Vinted with CSRF
  extension/popup.html        origin + token

Endpoints used today (change injected.js if Vinted move them):

  GET  /api/v2/users/current
  GET  /api/v2/users/{id}/items?page=&per_page=96
  GET  /api/v2/catalogs
  POST /api/v2/photos                 (multipart)
  POST /api/v2/item_upload/photos     (fallback)
  POST /api/v2/items
  PUT  /api/v2/items/{id}
  DELETE /api/v2/items/{id}

Lane bridge HTTP (pairing token, CORS for chrome-extension://):

  GET  /api/bridge/me
  POST /api/bridge/heartbeat          returns pending jobs
  GET  /api/bridge/jobs
  POST /api/bridge/jobs/:id/result    { ok, remoteId, url, error, errorBody }
  POST /api/bridge/catalog            { items: [...], username, userId }
  POST /api/bridge/sold               { remoteId, soldPriceGbp }
  POST /api/bridge/identity           { username, userId }

Catalog IDs in src/lib/lane/categories.ts are currently null for Vinted.
injected.js resolves by catalog path/name against /api/v2/catalogs. If
that mapping is ambiguous, confirm the numeric catalogId and write it
into categories.ts (confirmed leaf). Do not guess.

Hourly publish cap defaults to 30/account. Do not raise it casually —
marketplace ToS risk.

Photos: file inputs become data URLs and the extension re-uploads them
to Vinted. eBay Inventory API requires publicly reachable http(s) URLs.
If you need object storage, add R2 (or equivalent) and store https URLs
on item_photos. Do not leave eBay publishes on data: URLs — they will
fail with a clear error, which is correct.

-----------------------------------
  1. Sign up (email/password is enabled).
  2. Settings → Channels → copy pairing token → pair extension.
  3. Connect Vinted. Status stays extension_offline until the vinted.co.uk
     tab heartbeats, then green and remote_username fills.

  6. New listing (or imported item): confirmed category, https photos for

  8. Activity shows request ids. Failed jobs retry. Closing the Vinted

regressed. Revert.

7b. VINTED PHONE CONNECT — WHAT CROSSLIST ACTUALLY DOES
-------------------------------------------------------
Researched 9 Sep 2026.

Crosslist desktop (their own docs):
  “make sure you are logged into the correct Vinted account in a new
  tab of the same browser you are using with Crosslist.”
  Vinted autodelist is Chrome-extension based. The computer must stay
  awake. This is NOT server-side Vinted OAuth — Vinted has no public
  seller API.

Crosslist iOS/Android (App Store):
  Native app. Connect opens an in-app browser sheet (WKWebView /
  Chrome Custom Tab) on vinted.co.uk. The user types email/password
  or uses Apple/Google/2FA on Vinted’s real page. The native layer
  then reads HttpOnly cookies (access_token_web, refresh_token_web)
  from the WebView cookie store and uploads them to Crosslist
  servers. Same pattern as Evriwhere’s published Vinted help:
  “After you successfully sign in, Evriwhere securely captures the
  authentication session from Vinted. The web browser sheet will
  close on its own.”

What a WEBSITE cannot do:
  • Read HttpOnly cookies on vinted.co.uk from another origin.
  • Iframe Vinted (X-Frame-Options).
  • Reverse-proxy Vinted login (that is phishing — do not).
  • Run an unpacked Chrome extension on iOS Safari.

What Lane ships instead (honest, working):

  1. Settings → Channels → “Create phone connect link”
     QR (generated locally — do not send the secret URL to a
     third-party QR CDN) + URL /connect/vinted/:id?k=secret (20 min).
  2. Phone opens Vinted’s real login (email, Apple, Google, 2FA).
  3. Capture paths that actually work:
       a. Android Firefox (or desktop Chrome) + Lane Bridge.
          Extension now has cookies permission and POSTs
          refresh_token_web to /api/bridge/session. Tokens are
          AES-256-GCM sealed on marketplace_accounts.oauth_*.
       b. Advanced paste of refresh_token_web on the phone page
          (never the password).
  4. Once a refresh token is stored, Lane refreshes it via
     POST https://www.vinted.co.uk/oauth/token
     grant_type=refresh_token, client_id=web
     and can sync wardrobe / publish / delist from the server.
     Datacentre IPs are often DataDome-blocked — if so, jobs
     park as waiting_for_browser and the extension is the fallback.

  iPhone first-time capture still needs a native WebView (Crosslist
  has an App Store binary; we do not). Do not fake a green connect
  after “I’ve signed in” with no token. A follow-up iOS app using
  WKWebView + HTTPCookieStore is the only way to match Crosslist’s
  one-tap iPhone connect exactly.

  Do NOT collect Vinted email+password on a Lane form even though
  POST /oauth/token grant_type=password exists. Owner rule.

7d. INVENTORY BULK + DELETE
---------------------------
Inventory list is 10 rows per page.

  Header checkbox = this page
  “Select all N” = every row matching the current filter
  Bulk bar: Publish, Delist, Delete, find/replace
  Delete removes Lane rows (photos, tags, channel_listings, jobs, sales).
  It does NOT end live marketplace listings — Delist first.
  Item page has a red Delete as well as Archive.

qty 0 ⇒ enqueue delist on remaining live/queued/waiting listings.
